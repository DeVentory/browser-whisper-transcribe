건 · 밖으로 보낸 요청이 페이지가 열린 뒤 데이터를 담아 내보낸 요청 수입니다. 전사하는 동안에도 0이어야 하고, 하나라도 생기면 빨간색으로 바뀝니다.

이 숫자는 페이지 코드가 직접 센 값이라, 코드가 바뀌면 믿을 수 없습니다. 확실히 확인하려면 브라우저 개발자 도구의 네트워크 탭을 여세요(Safari는 '개발자용' 메뉴 → '웹 검사기').

받아 온 파일 기록 보기 · 0건, 0곳

이 페이지, 전사 코드, 모델 파일을 내려받은 기록입니다. 받기만 한 것이라 위 숫자에는 들어가지 않습니다.

접속한 곳받은 것횟수받은 크기

    내보낸 요청은 fetch·XHR·WebSocket·sendBeacon을 셉니다. 받은 크기는 브라우저가 알려 주는 만큼만 나오고, 캐시에서 읽은 파일은 빠질 수 있습니다.

    ⚖️ 브라우저에서 처리하면 달라지는 점

    서버에 파일을 올려 처리하는 서비스와 달리, 이 사이트는 내 기기의 브라우저에서 받아 적습니다.

    ✅ 좋은 점

    • 가입·설치 없이 링크만 열면 됩니다.
    • 파일을 올리지 않아 업로드를 기다리지 않습니다.
    • 사용료가 없습니다.
    • 파일이 내 기기 밖으로 나가지 않습니다.

    ⚠️ 아쉬운 점

    • 처음 한 번 모델을 내려받아야 합니다(약 0.17~1.6GB).
    • 속도가 기기 성능에 달려 있고, GPU를 못 쓰면 많이 느립니다.
    • 전사하는 동안 탭을 열어 두어야 합니다. 닫혀도 중간 결과는 기본으로 저장해 둡니다.
    • 코드·모델을 받는 서비스(jsdelivr, Hugging Face)에는 IP 같은 접속 정보가 보입니다.

    ❓ 자주 묻는 질문

    처음에 왜 오래 걸리나요? 얼마나 내려받나요?

    받아 적는 데 쓰는 모델 파일을 처음 한 번 내려받기 때문입니다. 내려받은 모델은 브라우저에 보관되어 보통 다음부터는 다시 받지 않지만, 브라우저 저장 공간이 부족하면 지워질 수 있습니다. 휴대폰 데이터로 받을 때는 용량에 주의하세요.

    모델GPU(WebGPU)CPU(WASM)
    🚀 large-v3-turbo약 1.6GB약 1.1GB
    ⚖️ small약 0.4GB약 0.25GB
    ⚡ base약 0.17GB약 0.08GB

    Hugging Face 파일 목록 기준(2026-11-09).

    어떤 모델을 골라야 하나요?

    정확도가 가장 중요하면 turbo입니다. 휴대폰이거나 용량·메모리가 걱정되면 small을 고르세요. base는 가장 가볍지만 한국어를 자주 잘못 알아듣습니다.

    여러 언어가 섞여 있으면 어떻게 하나요?

    언어 칸에서 '자동 감지'를 고르세요. 30초 구간마다 말하는 언어를 알아내 그 언어로 받아 적고, 감지된 언어를 결과 아래에 보여 줍니다. 한 구간 안에서 언어가 번갈아 나오면 더 많이 쓰인 쪽 하나로 정해져서, 다른 언어 부분은 틀리게 적힐 수 있습니다. 언어를 알아내는 단계가 더해지는 만큼 조금 더 걸립니다.

    휴대폰에서도 되나요?

    휴대폰은 메모리가 넉넉하지 않아 큰 모델(turbo)이 중간에 멈출 수 있어서, 휴대폰과 태블릿에서는 small을 기본으로 골라 둡니다. 전사하는 동안에는 화면을 켜 두세요. 아이폰·아이패드에서는 아직 직접 확인하지 못했습니다.

    얼마나 긴 파일까지 되나요?

    파일은 약 2GB까지 열 수 있고, 1시간이 넘는 강의도 끝까지 받아 적습니다. 2시간이 넘으면 메모리가 모자랄 수 있습니다. 한 구간에서 모델이 멈추면 그 30초를 건너뛰고 이어가며, 건너뛴 구간은 결과 아래에 알려 드립니다.

    결과가 틀리면 어떻게 하나요?

    조용하거나 끊긴 구간에서는 말하지 않은 문장(예: "이 영상은")이 나올 수 있고, base 모델은 한국어를 자주 잘못 알아듣습니다. 중요한 용도라면 결과를 직접 확인하세요. 전사된 길이가 파일보다 짧거나 건너뛴 구간이 있으면 결과 아래에 경고가 뜹니다.

    내 파일이 서버로 올라가나요?

    아니요, 올라가지 않도록 만들었습니다. 위쪽 "파일을 밖으로 보내지 않습니다" 칸에서 밖으로 보낸 요청 수를 직접 볼 수 있습니다. 다만 코드는 jsdelivr에서, 모델은 Hugging Face에서 내려받기 때문에 두 곳에는 내 접속 정보(IP 등)가 보입니다.

    📂 짧은 파일로 먼저 해 보세요

    짧은 파일과 small 모델로 시작하면 처음 내려받는 양도 적고, 결과가 어떤지 빠르게 볼 수 있습니다. 아래 버튼은 small 모델을 골라 둔 뒤 파일 창을 엽니다.

    📘 사용법과 개인정보

    • 📂 파일을 고르면 이 기기에서 소리만 꺼내 16kHz로 바꿉니다.
    • 🧠 모델은 처음 한 번 내려받습니다(용량은 위 질문 "처음에 왜 오래 걸리나요?"에 있습니다).
    • 🎧 30초씩 순서대로 받아 적고, 받아 적는 동안 글이 결과 칸에 차례로 나타납니다. 끝나면 구간·자막 형식으로도 볼 수 있고, 중간에 "중지"를 누르면 거기까지의 결과를 보여 줍니다.
    • 💻 GPU(WebGPU)가 있으면 빠르고, 없으면 CPU로 처리해 느립니다. 최신 Chrome·Edge를 권장합니다.
    • 🔒 파일 내용은 이 기기 밖으로 보내지 않습니다. 위쪽 "파일을 밖으로 보내지 않습니다" 칸에서 밖으로 보낸 요청 수를 직접 볼 수 있습니다.
    • 🛟 전사하는 동안의 중간 결과는 이 브라우저(IndexedDB)에 임시로 저장됩니다. 파일 이름과 전사된 글이 7일간 남고, 서버로는 보내지 않습니다. 공용 컴퓨터라면 결과 위쪽의 "지우기"를 누르거나 전사 버튼 아래의 저장 옵션을 끄세요.
    • 🌐 처음 접속하면 전사 코드는 cdn.jsdelivr.net에서, 모델은 huggingface.co·hf.co에서 내려받습니다. 이 서비스들에는 IP 같은 접속 정보가 보입니다.
    • ⚠️ 코드를 외부 CDN에서 받기 때문에, CDN이 해킹당하면 위 설명을 보장할 수 없습니다. 민감한 음성은 오프라인 도구가 더 안전합니다.
