# 웹 받아쓰기 (browser-whisper-transcribe)

음성·영상 파일을 **브라우저 안에서** 전사하는 정적 웹앱입니다. [Transformers.js](https://github.com/huggingface/transformers.js)와 Whisper(ONNX 변환 모델)를 WebGPU로 실행합니다. 전사 결과는 TXT·SRT·VTT·JSON으로 저장할 수 있습니다.

사이트: https://deventory.github.io/browser-whisper-transcribe/

## 사용법
1. 사이트를 엽니다(HTTPS 필요).
2. 파일을 끌어다 놓거나 **파일 열고 받아 적기**를 눌러 고릅니다(오디오·영상, 약 2GB 이하).
3. 모델과 언어를 고르고 **전사 시작**을 누릅니다. 처음에는 모델을 내려받습니다.

언어는 한국어·English·日本語 중에서 고르거나 **자동 감지**를 고를 수 있습니다. 자동 감지는 30초 구간마다 모델이 예측한 언어를 읽어 그 언어로 받아 적고, 감지된 언어를 결과 아래에 보여 줍니다. (Transformers.js는 언어를 지정하지 않으면 영어로 간주하므로, 감지는 앱이 모델의 언어 확률을 직접 읽어 구현했습니다.)

휴대폰·태블릿 같은 터치 기기에서는 탭 메모리 한도가 낮아 큰 모델이 중단될 수 있어, 기본 모델을 small로 고릅니다(추정에 따른 설정이며 실기기에서는 확인하지 못했습니다). turbo는 직접 고를 수 있습니다.

## 모델 용량 (Hugging Face 파일 목록 기준, 2026-11-09)
| 모델 | WebGPU(GPU) | WASM(CPU) |
|---|---|---|
| large-v3-turbo | 약 1.6GB | 약 1.1GB |
| small | 약 0.4GB | 약 0.25GB |
| base | 약 0.17GB | 약 0.08GB |

## 개인정보
- 파일 내용은 서버로 업로드되지 않도록 만들었습니다. base 모델로 25초 음성을 전사하는 동안 요청 34건을 기록했고 POST·PUT 요청은 0건이었습니다(turbo·small·WASM 경로는 이 방식으로 확인하지 않았습니다).
- 화면의 **확인 패널**("보내지 않았다는 걸, 직접 확인하세요")과 우측 상단의 업로드 배지는 페이지와 전사 워커가 낸 요청을 실시간으로 세어 보여 줍니다. fetch·XHR·WebSocket·sendBeacon으로 데이터를 보내면 업로드 수가 올라가고 빨간색으로 바뀝니다.
  - 이 값은 **페이지 코드가 스스로 센 것**이라, 코드가 바뀌면 믿을 수 없습니다. 확실히 확인하려면 브라우저 개발자 도구의 네트워크 탭을 직접 여세요.
  - 요청 수와 받은 크기는 브라우저가 기록해 준 것만 나옵니다. 캐시에서 읽은 파일은 빠질 수 있고, 다른 서버의 파일은 크기를 알려 주지 않아 "확인 불가"로 표시됩니다.
- **임시 저장**: 전사하는 동안 30초 구간이 끝날 때마다 결과를 이 브라우저의 IndexedDB에 저장합니다. 파일 이름과 전사 텍스트가 7일간 남고, 서버로는 보내지 않습니다. 결과 위쪽의 "지우기"로 바로 지울 수 있고, 전사 버튼 아래의 저장 옵션을 끄면 기존 기록도 지우고 더 저장하지 않습니다. 공용 컴퓨터에서는 끄거나 지우세요.
- 코드는 `cdn.jsdelivr.net`에서, 모델은 `huggingface.co`·`*.hf.co`에서 내려받으며 이 서비스들에는 IP 같은 접속 정보가 보입니다.
- 코드가 외부 CDN에서 로드되므로 CDN이 침해되면 위 설명이 성립하지 않을 수 있습니다. 민감한 음성은 오프라인 도구를 쓰는 편이 안전합니다.

## 긴 파일을 위한 장치
- 30초 단위로 순서대로 받아 적고, 한 구간이 제한 시간(WebGPU 60초, CPU 300초) 안에 끝나지 않으면 모델을 다시 불러오고 그 30초를 건너뛰어 이어갑니다. 건너뛴 구간과 오류는 경고로 알려 주고, 그때까지의 결과는 버리지 않습니다.
- **진행 중에 보이는 것**: 구간이 끝날 때마다 받아 적은 글이 결과 칸에 바로 나타나고, 진행률과 남은 시간(처리 속도로 계산한 추정치)을 보여 줍니다. 스크린리더에는 진행률을 10% 단위로만 알립니다.
- **중지**: 전사 중에 "⏹ 중지"를 누르면 그때 처리 중이던 구간은 버리고, 그 앞까지 받아 적은 결과를 보여 줍니다. 다시 시작하면 모델을 새로 준비합니다.
- **창을 닫아도 결과를 살리기**: 전사 중에 탭을 닫거나 새로고침하려 하면 확인창이 뜹니다(문구는 브라우저가 정하고, 휴대폰에서는 뜨지 않을 수 있습니다). 그래도 닫히면 다시 열었을 때 "저장된 전사 기록" 배너에서 지금까지의 결과를 불러올 수 있습니다. 이어서 전사하는 기능은 아직 없어서, 중단된 기록은 멈춘 지점까지만 있고 나머지는 같은 파일로 다시 전사해야 합니다.
- 소리가 거의 없는 구간은 모델에 넣지 않고, 같은 문장이 4번 이상 연속되면 환각으로 보고 제거합니다. 파일 길이보다 전사된 길이가 짧으면 경고합니다.
- **Safari의 MP4 오디오 잘림**: Safari(WebKit)의 오디오 디코더가 mp4·m4a·mov의 오디오를 중간에 조용히 잘라 내는 문제를 확인했습니다(80분 영상이 약 7분까지만 나옴). Safari에서 AAC mp4·m4a(HE-AAC 포함)는 컨테이너를 직접 읽어 5분 단위로 디코딩하는 방식으로 우회합니다. QuickTime(.mov)은 소리 정보가 한 겹 더 깊이 들어 있어 그 안에서 AAC 설정을 찾아 읽고, 브라우저가 파일을 못 읽을 때도 이 방식으로 한 번 더 시도합니다. 조각난(fragmented) mp4는 이 방식을 쓰지 않고 브라우저 기본 디코더로 읽으며, 길이가 짧게 읽히면 경고합니다.

## 시험한 것 (작성자 개인 환경, 한계가 있음)
- 맥북(M5 Pro), Chrome 헤드리스, WebGPU: large-v3-turbo로 한국어 강의 영상 1개(33분)를 156~224초에 전사했습니다(시험 시점에 따라 편차). 같은 영상을 mlx-whisper(맥용 네이티브)로 전사한 결과와 글자 기준 유사도 99.5%였습니다. 시험한 영상은 이 1개와 합성 음성뿐이라 다른 음성에서의 정확도는 알 수 없습니다.
- 같은 환경에서 mlx-whisper가 5분 음성을 7.6초에 처리해, 이 웹앱은 그보다 느렸습니다(약 4배, 29초).
- WebGPU를 끈 환경(WASM)에서 base 모델이 동작함을 확인했습니다.
- Safari: 80분 길이 mp4가 끝까지 전사되는 것을 맥의 Safari에서 확인했습니다(소요 시간과 모델은 기록하지 않았습니다). 같은 파일이 Chrome에서도 끝까지 전사됐습니다.
- 임시 저장: WebKit에서 5분 mp3(base 모델)를 끝까지 전사한 뒤 새로고침하면 복구한 텍스트가 원본과 같았고(60구간), 전사 도중 새로고침하면 그때까지 저장된 구간(25초분)이 "중단된 기록"으로 복구됐습니다. 닫기 확인창이 실제로 뜨는 것도 확인했습니다.
- 자동 감지: 한국어 강의 45초는 한국어(확률 99% 이상)로 감지되어 한국어 고정과 결과가 100% 같았고, 한국어·영어 문장이 번갈아 나오는 21초 합성 음성은 영어(58%)로 감지되어 두 언어가 모두 적혔지만 일부("페이지 테이블")가 영어로 바뀌었습니다. WebGPU(small)와 CPU(base) 모두 감지가 동작했습니다.
- 파일 형식(맥 Safari 27.2, 5분짜리 합성 파일): mp3 5종(16·24·32kbps·128kbps 스테레오·VBR), AAC-LC m4a·mp4, HE-AAC v1·v2, 조각난 mp4·m4a, `.mov`(ffmpeg가 만든 QuickTime)가 모두 끝까지(298.7초) 읽혔고, 조각난 mp4와 일반 mp4는 20분짜리도 끝까지 읽혔습니다. 같은 한국어 강의 45초를 담아 전사했을 때 원본 wav 결과와의 글자 유사도는 AAC-LC·.mov·조각난 mp4 99.1%, HE-AAC 94~96%, 16kbps mp3 90%였습니다. HE-AAC와 mp3의 차이는 ffmpeg로 푼 결과도 비슷해(94~95%, 91%) 코덱 압축 손실로 보입니다.
- **시험하지 못한 것**: iPhone·iPad 실기기(Safari 포함), 아이폰이 직접 찍은 `.MOV` 파일(구조가 시험한 파일과 다를 수 있음), 브라우저 캐시를 쓴 재실행, 용어 입력 기능(없음).

## 알려진 한계
- 무음 구간이나 잘린 파일에서 없는 문장("이 영상은" 등)이 나올 수 있습니다.
- base 모델은 한국어 오인식이 많습니다.
- GPU가 fp16을 지원하지 않거나 WebGPU가 없으면 CPU로 동작해 느립니다.
- 모델 저장소는 커밋 해시로 고정했지만, 저장소가 삭제되면 동작하지 않습니다.
- 자동 감지는 30초 구간마다 언어를 하나만 고르므로, 한 구간 안에서 언어가 번갈아 나오면 더 많이 쓰인 쪽으로 정해지고 다른 쪽이 틀릴 수 있습니다. 한 문장 안에서 섞이는 경우는 시험하지 못했습니다. 한 가지 언어만 쓴 파일이라면 직접 고르는 편이 더 안정적일 수 있습니다(추정).
- 휴대폰에서는 메모리 때문에 큰 모델이 중단될 수 있습니다(추정).
- 파일 머리에 적힌 길이보다 실제 오디오가 짧은 파일(예: 잘라 붙이다 헤더가 그대로 남은 mp3)은 실제 내용까지만 읽히고, 앱은 "파일 길이보다 소리가 짧게 읽혔다"는 경고를 띄웁니다. Safari만의 문제가 아니라 ffmpeg도 같은 지점에서 끝났습니다. 이런 경우 다른 형식으로 다시 내보내 보세요.
